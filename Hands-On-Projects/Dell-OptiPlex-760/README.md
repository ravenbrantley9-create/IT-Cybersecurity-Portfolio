# 🖥️ Dell OptiPlex 760 Troubleshooting & Rebuild

## 📌 Project Overview

This project documents my hands-on troubleshooting of a donated Dell OptiPlex 760 desktop computer.

I used the computer as a learning project while developing my IT support and computer hardware skills. Instead of replacing components immediately, I worked through the system step-by-step to identify possible causes of its startup and hardware problems.

This project gave me practical experience working inside a desktop computer, isolating hardware components, interpreting system behavior, and documenting a troubleshooting process.

---

## 🎯 Project Goals

- Learn the internal components of a desktop computer
- Practice safe hardware removal and installation
- Diagnose startup and POST problems
- Test RAM modules and memory slots
- Learn how storage and optical drives connect to the motherboard
- Run hardware diagnostics
- Prepare the computer for an operating system installation
- Document the troubleshooting process

## 🔎 Initial Inspection

I began by opening the Dell OptiPlex and identifying the major internal components.

I inspected components and connections including:

- Motherboard
- RAM modules and RAM slots
- Hard drive
- DVD/optical drive
- Power connections
- Data cables
- CMOS battery
- Cooling components

The computer powered on, but troubleshooting was required to determine the cause of startup errors and system behavior.

---

## 🧠 RAM Troubleshooting

One of the major troubleshooting steps involved testing the computer's memory.

I:

1. Located the RAM modules and memory slots.
2. Removed RAM modules for individual testing.
3. Attempted startup with different RAM configurations.
4. Compared the computer's beep-code behavior.
5. Identified that one RAM configuration behaved differently from another.
6. Continued testing using the RAM module that produced the better result.

This helped me understand how technicians isolate memory problems instead of replacing several components at once.

---

## 💾 Hard Drive Troubleshooting

During troubleshooting, I disconnected and removed the hard drive.

This allowed me to determine whether the storage device was contributing to the startup problem and gave me hands-on experience identifying the drive's power and data connections.

The hard drive was intentionally left disconnected during part of the diagnostic process.

---

## 💿 DVD / Optical Drive

I also disconnected and removed the DVD/optical drive.

Removing the drive:

- Improved access to internal components
- Made the RAM slots easier to reach
- Allowed additional hardware testing
- Helped isolate unnecessary components during troubleshooting

---

## 🔋 CMOS / Motherboard Troubleshooting

I located the CMOS battery and worked through troubleshooting involving the motherboard and system configuration.

This helped me learn the purpose of the CMOS battery and how stored BIOS/firmware settings can be involved in PC troubleshooting.

---

## 🧪 Hardware Diagnostics

After working through the hardware components, I ran the computer's built-in diagnostics.

Instead of immediately replacing additional parts, I used the diagnostic process to gather more information about the computer's condition.

This reinforced an important troubleshooting principle:

> Test and isolate the problem before replacing parts.

---

## 🛠️ Troubleshooting Method

Throughout the project, I followed a basic IT troubleshooting process:

1. Identify the problem
2. Inspect the hardware
3. Disconnect unnecessary components
4. Test one component or configuration at a time
5. Observe startup behavior and beep codes
6. Run hardware diagnostics
7. Document the results
8. Determine the next step
